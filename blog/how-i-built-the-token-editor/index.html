Case Study

How I rebuilt a Figma component as accessible HTML

15 March 2026 4 min read
CSS Accessibility Design Tokens Figma

Every design system starts with a component library in Figma. But Figma components don't render in the browser. At some point, someone has to translate those carefully crafted auto-layout frames, corner radii, and colour variables into actual HTML and CSS. That's what I did with the Token Editor — and here's how the translation worked.

The Figma source

The original Token Editor component in Figma was a modal panel with a structured list of design tokens. It used auto-layout for spacing, component properties for variant states (expanded/collapsed, valid/error), and a set of colour styles mapped to semantic names like token/value/error and token/background/readonly.

The design specified:

  • A modal overlay with backdrop-filter: blur(8px)
  • Token rows with left-aligned labels and right-aligned value inputs
  • Error states with a red left border and an icon + message below the input
  • Collapsible groups with chevron rotation on expand
  • Keyboard-navigable focus rings matching the Figma spec (2px offset, 2px stroke)

Translating tokens to CSS custom properties

The first step was mapping Figma colour styles to CSS custom properties. Figma's colour styles don't export as variables — they're just hex values attached to layers. So I built a naming convention that mirrored Figma's structure:

:root {
  --color-token-bg: #f7f6f3;
  --color-token-border: rgba(0, 0, 0, 0.1);
  --color-token-error: #c1292e;
  --color-token-focus: #534ab7;
  --color-token-value: #1a1a18;
  --color-token-label: #6b6a65;
}

Each CSS variable maps directly to a Figma colour style. The naming convention follows the pattern --color-{domain}-{element}-{state}, which mirrors how Figma organises its style library. This means when a designer updates a colour in Figma, the developer knows exactly which CSS variable to change — no guessing.

Building the accessible structure

The modal itself became a <dialog> element, which gives us free escape-key handling, focus trapping, and proper ARIA semantics. Each token group became a <details> element — native disclosure widget, zero JavaScript needed for the expand/collapse behaviour.

The trickiest part was the error states. Each input needed an aria-describedby pointing to its error message, and the error message needed to appear and disappear without causing layout shift. I solved that with a reserved min-height and CSS transitions on opacity:

.token-input__error {
  min-height: 1.5em;
  opacity: 0;
  transition: opacity 150ms ease;
}

.token-input__error[aria-hidden="false"] {
  opacity: 1;
}

What I learned

The biggest takeaway: Figma's auto-layout is conceptually close to CSS flexbox, but the details matter. Figma's "padding" on a frame is actually padding on a flex container — but Figma doesn't distinguish between gap and padding the way CSS does. You have to inspect the spacing between items to figure out what should be gap and what should be padding.

The second lesson: design tokens in Figma are only as useful as the naming convention. If your Figma styles are called "Blue / 500" and "Gray / 100", the developer has no idea what they mean semantically. If they're called "Border / Default" and "Background / Secondary", the translation to CSS is nearly automatic.

The Token Editor is now live in the Work section. The full source is a single HTML file with inline CSS and vanilla JS — no build step, no framework, just the platform.
